# Демонстрация TRACECRAFT LABS

Этот сценарий показывает шесть работающих механизмов на вымышленных Luma Field и
Veyra Works. Результаты поиска и измерения настоящие; ответы в fixture/local —
детерминированные, извлечённые из источников. Это не демонстрация качества живой LLM.
STC не найден и не подключён: `MISSING_PRIVATE_SOURCE`.

## Подготовка и запуск

Нужен Python 3.12+. При первом запуске из корня проекта:

```sh
make setup PYTHON=python3.12
make test
make check
make demo
make privacy-check
make serve
```

Откройте [локальное приложение](http://127.0.0.1:8317). Повторный запуск после уже
выполненного setup — `make serve`; SQLite сохраняет состояние между запусками.
Полные команды установки и ограничения окружения — в [README](../README.md).

Реальный dense/hybrid-поиск требует отдельной подготовки модели. Пока сервер
остановлен, выполните:

```sh
make models
make eval-local
make eval-independent
make serve
```

`make models` явно загружает закреплённую multilingual-e5-small. После подготовки
local-профиль использует CPU и локальные файлы; недоступность модели показывается
как блокировка. В текущем рабочем окружении модель подготовлена и local-отчёты
получены; в чистой копии веса необходимо подготовить снова. Модель и runtime не
входят в публичный экспорт.

Эксперименты CLI запускайте до сервера либо с отдельной базой, например:

```sh
PYTHONPATH=src .venv/bin/python -m tracecraft --db runtime/experiment.sqlite experiment atlas --mode local
```

## 1. ATLAS — от вопроса к источнику

Откройте **ATLAS**. Выберите Luma Field, v2, Fixture. Спросите «Какой основной цвет
бренда?». Проверьте lexical-выдачу, статус ответа и цитаты. Dense и hybrid в fixture
не должны выглядеть как выполненный семантический поиск.

Переключитесь на Local и повторите запрос. Теперь сравните три выдачи. Нажмите на
найденный фрагмент: инспектор показывает текст, раздел, версию, статус, происхождение
и hash. Это позволяет проверить существование источника отдельно от поддержки
утверждения.

Проверьте кнопки примеров: точный токен, перефразирование, неизвестный ответ и конфликт
цвета ленты упаковки. Источники не разрешают конфликт по времени изменения. Нижние
панели **Reproduce / Config / Data / Report** показывают запуск, настройки, корпус
и сохранённый отчёт. Команда отдельного эксперимента: `make atlas`.

## 2. ECHO — безопасное повторение и обязательный промах

Откройте **ECHO**, выберите Local и Semantic. Выполните `What is the primary color?`,
затем `Tell me the primary colour.`. Посмотрите `reason`, тип попадания, реальное
число вызовов и время. Конкретное поведение зависит от текущего содержимого кэша;
для сравнения с чистым контролем нажмите **Compare all policies**.

В этом эксперименте девять запросов проходят off/exact/semantic. Среди обязательных
промахов — другой бренд, версия, число, отрицание, уточнение и отзыв доступа. Не
называйте два попадания доказательством общей безопасности или экономии денег.
Смотрите фактическую задержку: более низкое число вызовов не гарантирует ускорения.
Команда: `make echo`.

## 3. RELAY — уточнение, перезапуск, согласование

Откройте **RELAY**, Fixture. Для воспроизводимого узкого примера задайте цель
`brand logo banner`, текст `Explore more`, а размеры оставьте пустыми. Нажмите
**Start workflow**. Состояние должно перейти в `awaiting_input`, с вопросами о
ширине и высоте. Сохраните отображённый Run ID.

Для ручной проверки сохранения состояния остановите сервер `Ctrl+C`, снова
выполните `make serve` и откройте RELAY. Введите Run ID в **Saved run identifier**,
нажмите **Load checkpoint**. Задайте 1200 × 628, затем **Submit clarification &
resume**. Это продолжение того же запуска.

При `awaiting_approval` прочитайте три вкладки: requirements, questions и handoff.
Проверьте ссылки на правила и hashes. Только после просмотра нажмите **Approve this
exact handoff**. Успешное состояние относится к этому комплекту и этим входам.
Проверка устаревшего approval и повторного выполнения входит в `make relay` и
тесты; автоматическое согласование в CLI-эксперименте не выдаётся за решение человека.
RELAY готовит пакет дизайнеру, а не пиксели баннера.

## 4. LENS — сбой, свидетельства, черновик теста

Откройте **LENS**. Через **Recent runs** можно выбрать предыдущий запуск. Просмотрите
реальные stages, входы, выходы, ошибки и связанные span IDs. Запись сама по себе не
доказывает причину ошибки.

Для воспроизводимого инцидента выберите **Invalid tool arguments**, нажмите
**Create diagnostic incident**. В отчёте сравните наблюдаемый сбой, воспроизведение
и проверку ограниченного исправления. Нажмите **Create regression draft**: это
черновик, его ожидаемое поведение ещё требует отдельного подтверждения. Команда:
`make lens`.

## 5. SENTINEL — повреждённый и обычный кандидат

Откройте **SENTINEL**, Fixture. Сначала выберите fault-injected candidate и нажмите
**Compare actual outputs**. Gate должен опираться на действительно испорченные
утверждения/цитаты. Откройте строку случая через **Inspect outputs** и сравните
baseline с candidate.

Затем выберите normal configuration. В сохранённом исследовании обе обычные
конфигурации проходят 32/32 исходных случаев, и gate — `PASS`. У повреждённого
кандидата — 5/32 и 27 регрессий. Это не покрывает отдельные ошибки независимого
challenge. Политика блокировки критических ошибок остаётся. Команда
`make sentinel` также сохраняет отрицательный контроль `NOT_COMPARABLE` при
необъявленном изменении условий.

## 6. CANON — увидеть покрытие и оставшиеся ошибки

Откройте **CANON**. Запустите Lexical, затем при готовой модели Dense или Hybrid.
Просмотрите категории и фильтры split. Нажмите на ID вопроса, чтобы увидеть gold,
исходные evidence spans и фактический ответ. Gold не находится в поисковом индексе.

Сохранённые local-сравнения проходят 32 из 32 исходных случаев. Эти вопросы были
доступны при разработке и стали регрессионным набором. Команда: `make canon`.

Затем откройте [независимый отчёт](../reports/public/independent-quality.json). Первый
набор улучшился с 20/23 до 23/23 после раскрытия вопросов; три случая не оценивались
из-за неопределённости. Второй набор из 12 вопросов был скрыт до финальной фиксации
кода: результат остался 7/12. Пять вопросов об отсутствующих атрибутах ошибочно
получили `supported`. Для воспроизведения: `make eval-independent`; смотрите два
JSON в `runtime/`, завершение команды не означает прохождение всех случаев.

В ATLAS выберите Veyra Works и спросите `What is the maximum permitted width for
the Veyra Works wordmark?`. Руководство задаёт минимум, не максимум. Проверьте,
отвечает ли показанная настоящая цитата именно на вопрос: это демонстрация
оставшегося ограничения, а не подтверждение правильности ответа.

## Запись результата и скриншоты

`make demo` выполняет все fixture-эксперименты; `make eval-local` — local-профили.
Смотрите `reports/public/<module>-fixture.json` и `<module>-local.json`, а также
`RUNS_MANIFEST.json`. Кнопка **Download current JSON** выгружает показанный результат;
**Report** открывает сохранённый эксперимент, а не запускает новый.

Переключение в **Replay** загружает исторический отчёт. Его время относится к
записанному запуску. Браузерный Live отключён; платные вызовы в этом демо не нужны
и не выполняются автоматически.

Для портфолио снимайте только реально открытые страницы на этих публичных данных.
На кадре должны оставаться режим, выбранный корпус и видимый статус результата.
Не превращайте непройденный benchmark в зелёный показатель и не подменяйте
скриншот макетом. Ручная проверка на физическом мобильном устройстве не следует
из наличия адаптивной вёрстки или desktop viewport-проверки.
